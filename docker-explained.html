「我電腦上可以跑啊」：Docker 到底把什麼裝進箱子？

工程師把程式交過來，語氣很穩：「我電腦上可以跑啊。」同事一打開，畫面卻是一排錯誤。兩個人都沒說謊，只是兩台電腦各有各的脾氣：裝的東西不一樣，同一份程式就會走出兩種結果。

箱子裡疊的是程式、函式庫與設定。箱子只是比喻，下面說明實際裝進去的是什麼。
!

閱讀說明：這篇是概念介紹，不是安裝教學，也不是 Docker 公司的宣傳，本站與其沒有合作。技術敘述依 Docker 官方文件整理，用自己的話改寫。比喻用來帶路，每段比喻後面都接著實際機制。

01

同一份程式，兩台電腦卻各跑各的

你的電腦上，執行環境是某一版，需要的套件都裝了，程式就跑得動。同事的電腦是另一版，少一個套件，或已經裝了會互相打架的軟體，同一份程式就報錯。沒有人在說謊。差的是兩台電腦裡已經存在的東西。

Docker 官方文件描述的是同一件事：團隊成員、持續整合系統、正式環境裝的版本不一樣，或跟這台電腦上已經裝好的軟體互相衝突。程式要能換地方跑，就不能只把程式碼傳過去，還得把「它在什麼環境裡才跑得起來」一起說清楚。

官方概觀把 Docker 定義成一個開放平台，用來開發、交付、執行應用程式。它把應用程式包進一個「鬆散隔離」（loosely isolated）的環境裡執行。這個環境叫容器（container）。容器裡帶著執行應用程式需要的東西，所以不必先假設主機上已經裝好同樣的軟體。分享給別人時，對方拿到的是同一個容器，以同樣方式運作。

這裡說的「不必依賴主機上裝了什麼」，指的是函式庫、設定這類檔案。容器仍然要借用主機的作業系統核心。核心是什麼、為什麼這樣比較省，下一頁說明。

白話比喻

搬家時若只帶一張食譜，新廚房沒有那口鍋、沒有那種醬，菜還是做不出來。比較穩的做法，是把整套廚具和調味料一起裝箱搬過去。容器想做的，就是這口箱子：程式連同它需要的檔案一起走。

比喻停在這裡，實際機制不是一台縮小的電腦。容器是一個被隔離的「行程」（正在執行的程式），帶著它需要的檔案。官方文件整理的特性有四個。自給自足：不靠主機事先裝好相依的套件。隔離：跟別的程式隔開。彼此獨立：刪掉一個，其他的還在。可攜：開發者的筆電、資料中心、雲端，都可以用同樣方式跑。

延伸閱讀

容器本質上也是一種「別人接得走、驗得過」的交接包。東西若只留在某一台電腦或某一次對話裡，下一個人還是接不走。可以接著看《跟 AI 聊完了，為什麼還是交不出可交接的東西？》。

容器和虛擬機，差在核心是不是共用

白話比喻

虛擬機（virtual machine）像公寓的每一戶都自備整套水電管線，從表到管都是自己的。容器像同一棟樓裡的房間，隔開的是房間，地基是整棟樓共用的。

公寓的比喻只說到一半，真正的差別在核心。官方文件的說明是：虛擬機是一整套作業系統，有自己的核心（kernel）、硬體驅動程式，以及上面的程式。硬體驅動程式是讓系統認得硬碟、網路卡這些硬體的程式。只為了把一個應用程式隔開，就開一整台虛擬機，負擔很大。

核心是作業系統最底層、負責分配處理器、記憶體、檔案與網路給各個程式的那一塊。容器是帶著所需檔案的隔離行程，多個容器共用同一個主機核心。同一台機器上，因此可以同時跑更多應用程式。

官方概觀把 Docker 描述為：在以超管理器（hypervisor）為基礎的虛擬機之外，另一種較省資源的做法。超管理器是負責在一台實體機器上開出多台虛擬機的那層軟體。這裡只保留這個定性描述：同樣的硬體可以承載更多工作。

兩者常常一起用，不是二選一。雲端上租到的機器，通常本身就是一台虛擬機。在這台虛擬機裡裝上容器執行環境，就可以跑好幾個容器化的應用程式。

03

看得到什麼，和能用多少，是兩件事

執行容器時，Docker 會替它建立一組命名空間（namespaces）與控制群組（control groups）。兩套機制管的事情不一樣。

命名空間決定「看得到什麼」。容器裡的行程看不到、也影響不到其他容器或主機上的行程。每個容器有自己的網路堆疊。網路堆疊是處理網路連線的那一組功能；各有一份，這個容器的網路就跟別的容器分開。官方概觀也說明，容器預設與其他容器、主機相對隔開，網路與儲存隔到什麼程度，還可以再調整。

控制群組決定「能用多少」。它計量並限制記憶體、處理器、磁碟讀寫，避免單一容器把整台機器的資源用光。官方文件也寫明：控制群組不負責防止一個容器去讀另一個容器的資料。那是命名空間和其他機制的工作。

02 · 共用核心
04

Dockerfile：一行一行的步驟

白話比喻

Dockerfile 像食譜。它本身不是那盤菜，它寫的是：從哪一種底開始、放進哪些材料、加熱時做什麼、上桌時預設端出哪一道。

實際機制是一份純文字檔。撰寫說明與Dockerfile 參考都把它定義成建立映像檔的文字文件。Docker 讀這份檔案，照裡面的指令自動建置映像檔。常見的一行一行是這樣：FROM 指定從哪個基底映像檔開始；COPY 複製哪些檔案進去；RUN 執行什麼指令來安裝東西；CMD 寫容器啟動時預設要執行什麼。基底映像檔就是起點：先站在一個已經做好的映像檔上，再往上加你自己的步驟。

05

映像檔：封好的唯讀範本

白話比喻

映像檔像照食譜做好、封好的冷凍料理包。食譜可以再改，已經封進這包的內容不會在架子上自己變。

實際機制是一個唯讀範本（image）。官方說明：映像檔裡有執行容器需要的檔案、函式庫與設定。兩個原則要一起記。建立之後不能修改，要改就做新的一版。它由一層一層組成，每一層是一組檔案變更：新增、刪除或修改。

Dockerfile 的每一道指令會在映像檔裡產生一層。改了 Dockerfile 再重新建置時，只有變動的層需要重建。不同的映像檔可以共用同一個基底層，儲存與傳輸就不必每一包都從零再搬一次。關於層的說明還補了一點：執行時用聯合檔案系統（union filesystem）把這些層疊成同一個畫面，容器看到的是疊好之後的結果。原本的每一層維持不動。

06

容器：映像檔跑起來的那一份

白話比喻

容器像把冷凍料理包加熱之後、正在上桌的那一盤。同一包可以做出很多盤。吃完的盤子收掉，料理包本身不會因此改寫。

實際機制是映像檔的執行實例。概觀說，容器可以建立、啟動、停止、移動、刪除。建立容器時，Docker 在底下那些唯讀的映像檔層上面，替這個容器加一層薄薄的可寫層。儲存驅動程式的說明寫得很直接：容器執行時新增、修改、刪除的檔案，都寫在這一層。要改下層已經存在的檔案時，才把那個檔案複製上來再改，這叫寫時複製（copy-on-write），底下的原層不動。

所以同一個映像檔可以同時跑很多個容器，各有各的資料狀態。刪除容器時，可寫層跟著刪除，映像檔不變。沒有另外存起來的變更，會跟著容器一起消失。需要保留的資料要放在磁碟區（volumes）。磁碟區由 Docker 建立與管理，不會因為刪掉容器而消失。

07

映像檔倉庫：大家去放、去拿的地方

白話比喻

映像檔倉庫像大家共用的食材櫃。做好的料理包可以放進去，別人也能從同一格取出同一包。

實際機制是集中存放與分享映像檔的地方。官方說明：倉庫（registry）可以公開，也可以私有。Docker Hub 是任何人都能用的公開倉庫，也是 Docker 預設去找映像檔的地方。公司可以自架私有倉庫。倉庫和儲存庫（repository）不是同一個詞。倉庫是整座櫃子；儲存庫是裡面依專案分開的一格。同一個儲存庫可以放多個版本標籤，例如 v1.0、v2.0。放上去用 docker push，取出來用 docker pull。

下面兩行只是把名詞對上一個最小的動作，不是安裝步驟，也沒有列出執行後會印出的整段文字。

docker run hello-world
docker ps -a

第一行叫 Docker 用 hello-world 這個測試映像檔跑一個容器。官方安裝頁的驗證說明是：本機還沒有這個映像檔時，會先從預設的映像檔倉庫下載，在容器裡執行，印出一段確認訊息後結束。概觀裡對 docker run 的流程寫得更完整：本機沒有映像檔就先拉下來，建立容器，在最上層配置一個可讀寫的檔案系統，建立網路介面，然後啟動並執行指令。指令結束後容器會停止，但不會自動刪除。

第二行列出容器。docker ps 的參考頁寫明：docker ps 預設只列出執行中的容器。hello-world 印完確認訊息就結束了，所以要加 -a，才看得到剛才那個已經結束的容器。在 Linux 上，這兩行前面可能要再加 sudo。本文不貼出任何示範輸出，只說明它會印出一段確認訊息。

延伸閱讀

映像檔用版本標籤把環境固定在某一版。這和「供應商把預設換掉、線上行為就跟著變」是同一類問題：你以為拿的是昨天那個，其實起點已經換了。可以接著看《模型換代時，產品為什麼會突然變笨？》。

三種人為什麼需要 Docker（也可能不需要）

不是每個人都該為了這口箱子改工作方式。用軟體的人、寫程式的人、做決定的人，卡住的地方不一樣，用不到的時候也不一樣。

標示：下面每張卡的「Docker 怎麼幫」，技術機制依 Docker 官方概觀與容器說明。三張卡的「其實不需要的情況」，以及經營者這張卡怎麼取捨，是本站編輯觀點，不是官方文件說法。

使用者

痛點

安裝步驟一長串，版本對不上，程式在自己的電腦上壞掉。你要的是它跑起來，不是先搞清楚這台電腦還缺什麼。

Docker 怎麼幫

大多數一般使用者不會直接碰到 Docker。好處是間接的。官方文件說明，同一份打包方式可以在不同環境以同樣方式執行。團隊用同一份映像檔做測試與上線，使用者少碰到一點「到正式環境才壞」。

自己架設開源工具的進階使用者，才比較會直接用到。常可以用一個映像檔把程式、函式庫與設定一起跑起來，不必在自己的電腦上手動裝一長串相依套件。要哪一版，由映像檔的版本標籤固定。

其實不需要的情況

以下是本站編輯判斷。只用網頁服務，或只用手機、桌面應用程式的人，安裝與更新是那些軟體自己的事。Docker 不是一般消費軟體的安裝方式。對非工程背景的人，先安裝 Docker 本身就是多一道門檻。

開發者

痛點

每個人的環境不同。新成員把環境設定起來很耗時。測試與正式環境不一致，就會變成「我這邊可以、上線不行」。不同專案需要的套件版本若裝在同一台電腦，會互相衝突。這對得上官方文件描述的版本不一致，以及跟本機已經裝好的軟體互相衝突。

Docker 怎麼幫

Dockerfile把建立環境的步驟寫成文字檔，Docker 照它建出映像檔。同一份映像檔可以在筆電、持續整合與持續交付的流程、正式環境裡執行。一個應用程式若有多個元件，例如看得到的網頁、背後的程式、存資料的資料庫，可以各自放在自己的容器。各專案的套件留在各自的容器裡，不會擠在同一組安裝環境裡互相覆蓋。

其實不需要的情況

以下是本站編輯判斷。單一語言的小腳本、一份靜態網站，若大家執行方式都一樣、沒有環境差異，容器要處理的問題還沒出現。平台已經替你管理執行環境的服務，也不必再包一層。容器有學習成本，出問題時除錯會多一層。若要隔開的是完全不信任的程式，不應只靠容器的預設設定，理由在下一頁。

經營者

痛點

交付常常卡在環境：某人的電腦能跑，換一台就停。人員更替之後，沒有人會把環境架起來。想換雲端廠商，或把同一個服務擴充到別的地方時，又擔心被原來的做法綁住。

Docker 怎麼幫

環境可以重現，交接和上線比較能照同一份做法走，流程較可預期。這是編輯把可重現連到經營上的說法。容器可攜：同一種執行方式可以放在筆電、資料中心或雲端，搬遷和擴充因此多一點彈性。多一點，不是完全不綁廠商。資料庫、雲端專屬服務仍可能把資料和流程留在原來的地方。官方概觀把 Docker 描述為以超管理器為基礎的虛擬機之外、較省資源的做法。這裡只保留這個定性描述。

其實不需要的情況

以下是本站編輯觀點。映像檔和安全設定要有人維護；映像檔不會自己更新，隔離也不該被當成已經做完。學習與維運成本不會因為裝完就消失。大型組織使用 Docker Desktop 需要付費授權，範圍見下一頁，本文不是法律建議。產品若完全使用現成的雲端軟體，自己不把程式裝上去跑，就不必為了容器再做這筆安排。

延伸閱讀

保有「搬得走、換得掉」的能力，跟容器追求的可攜性是同一種思路：工作不要只活在某一台機器、或某一家供應商當下的預設裡。可以接著看《別把公司的記憶租給一顆模型》。

限制與風險

1. 容器不是和虛擬機同等的隔離牆。容器共用主機核心。Docker 官方安全性文件說明，執行容器的一個主要風險是：預設給容器的權限與掛載，可能單獨或配合核心漏洞，造成隔離不完整。官方建議只保留行程真正需要的權限，並以非最高權限帳號在容器內執行。最高權限帳號（root）是這台系統裡權限最高的那個帳號。「與虛擬機比較」是本站依官方描述整理的句子，官方文件沒有用這句話。

2. 能控制 Docker 的人，權限很大。官方文件說明，Docker 常駐程式預設需要最高權限帳號，除非改用 Rootless 模式。只有受信任的使用者可以控制它。它可以把主機目錄，甚至整個根目錄，分享給容器。根目錄是整台電腦檔案的最上層。一旦這樣分享，容器就能修改那些主機檔案。

3. 資料放錯地方會不見。寫在容器可寫層的資料，刪掉容器就沒了。要保留的資料要用磁碟區。

4. 映像檔要有人維護。映像檔建立後不會自己更新。基底映像檔有新版本時，要重新建置才會換上。這一點是編輯依「映像檔建立後不能修改」延伸的說法，不是官方文件的原句。

5. Docker Desktop 授權。Docker 官方授權頁寫明：Docker Desktop 對小型企業（員工少於 250 人「且」年營收少於 1,000 萬美元）、個人使用、教育、非商業開源專案免費；較大組織的專業使用、政府機關需要付費訂閱。Docker Engine 等開源專案的授權條款不受影響。以官方頁面為準，本文不是法律建議。查核日期 2026 年 9 月 29 日。

10

重點整理

1.「我電腦上可以跑」多半是環境不同。容器把程式和它需要的檔案、函式庫、設定一起打包。

2.容器是共用主機核心的隔離行程，靠命名空間（看得到什麼）與控制群組（能用多少）分隔。虛擬機有自己的作業系統與核心，較重。兩者常一起用。

3.Dockerfile 寫步驟，建置出唯讀、分層的映像檔。執行映像檔得到容器，容器的變更寫在自己的可寫層。

4.映像檔倉庫（例如 Docker Hub）負責存放與分享映像檔，用版本標籤區分版本。

5.使用者、開發者、經營者需要它的理由不同，也各自有不需要的情況。

6.不是每個團隊都需要。隔離有限制，資料要放磁碟區，映像檔要有人維護。大型組織使用 Docker Desktop 要注意授權。

給工程師的 Takeaway

以下是編輯根據本文延伸的實務建議，不是 Docker 官方說法，也不是已驗證的研究結論。

把「我電腦上可以跑」變成可重現。為一個你負責的小服務寫 Dockerfile，在沒有你個人設定的乾淨環境建置並執行。本機才有、別人沒有的隱藏相依，找出來寫進 Dockerfile。口頭能跑，只代表你的電腦剛好齊全。

固定版本，不要只靠預設標籤。Dockerfile 的基底映像檔寫明版本標籤，自己的映像檔也打上版本標籤。在說明文件記下哪個版本對應哪次上線。出問題時才有一個退得回去的版本，而不是一個會跟著倉庫變動的名字。

分清楚哪些資料要活過容器。列出容器會寫入的資料，例如上傳檔案、資料庫、日誌。標出哪些刪掉容器就會消失，把需要保留的改放磁碟區。並讓容器以非最高權限帳號執行，對上前面說的權限原則。

本週可以做

挑一個現有的小服務，寫好 Dockerfile，請一位同事在他的電腦上只用 docker build 與 docker run 兩個指令跑起來。驗收方式：同事不需要照口頭指示另外安裝任何套件就跑起來，而且說明文件寫明使用的映像檔標籤。若同事還得問你「要先裝什麼」，這個試驗就還沒完成。

給小主管的 Takeaway

以下是編輯根據本文延伸的實務建議，不是 Docker 官方說法，也不是已驗證的研究結論。範圍停在你帶得動的團隊：一份檢查表、一張分工、一次試點。

把「環境能重現」寫進驗收標準。在新人上手文件或交付檢查表加一條：專案能在乾淨環境用文件上的步驟跑起來。驗收看的是下一個人照文件做得到，而不是原作者在自己的電腦上做得到。

指定映像檔的負責人與更新節奏。誰負責基底映像檔更新、多久檢查一次，寫在團隊分工表上。映像檔不會自己提醒該更新了。分工表上沒有負責人，就沒有人管。

先試點，不全面推。挑一個環境問題最明顯的專案試用容器。授權是否在免費範圍，交給負責採購或資訊部門的同事確認。試點結束時，結論寫成列入容器化試點，或寫成暫不需要，並附上理由。

本週可以做

請一位新人或輪值同事照現有文件，從零設定一個專案，記錄每一步卡住的地方與花費時間。驗收方式：有一份卡點清單，每一步寫出花了多久、卡在什麼，並在清單上寫明「列入容器化試點」或「暫不需要」的結論與理由。沒有卡點紀錄，或沒有結論，這個試驗就還沒完成。

一句話帶走

「我電腦上可以跑」只說明了你的電腦。

容器把程式和它需要的檔案一起打包，換一台機器才有機會照同樣方式執行。隔離有限度，資料要放對地方，映像檔要有人維護。
